# 通知落地助手 · Notice-to-Task

> 把一条通知，变成一份能直接发班的任务包。

**在线演示**：https://jieshao321.github.io/notice-to-task-demo/

---

## 是什么

高校辅导员每周处理 3—5 条学校通知（评奖、选课、实习、考试）。一条 1200 字的通知，要做：

读三遍 → 摘要素 → 写群发文案 → 发 4 个群 → 挨个私聊没交的 → 建表登记

**访谈中位数：一条通知 60 分钟。**

已有的产品（教务问答机器人、校园百事通小程序）都停在「回答」这一层——**没有人做「辅导员拿到通知之后的那一段」**。

这个项目做那一段。

## 产出

一条通知进去，八行任务卡出来：

| | |
|---|---|
| 事项 | 这条通知到底是干什么的 |
| 对象 | 谁要参与 |
| 条件 | 参与门槛（逐条列） |
| 截止 | 保留原文表述 + 换算后的日期 |
| 材料 | 交什么、几份、要不要盖章 |
| 交到哪 | 线下地址 / 线上渠道 |
| 找谁 | 联系人 |
| 待确认 | 原文没写的，标出来问人，**不猜** |

外加五件工件：群发文案 · 催办计划 · 核验清单 · 未交名单 · 日历提醒。

## 三条硬约束

1. **只从原文抽取**——不推断、不补全，原文没写的填 `null` 进待确认
2. **每条结论回链原文**——点任意一行，高亮回到通知里那句话
3. **不自动发消息**——发出去的责任留在人这一侧

## 技术栈

**一个单智能体 + 一段 241 字提示词。没有编排、没有工作流、没有多智能体。**

| 项 | 值 |
|---|---|
| 平台 | 华为云 AgentArts |
| 模型 | `deepseek/deepseek-chat` |
| 系统提示词 | 241 字，五条规则 |
| 工具 / Skill | 无 |

实测单次调用：输入 46,575 tokens / 输出 459 tokens（大头是平台注入的系统上下文，不是通知本身）。

## 评测结果

20 条真实学校通知（已清洗），逐条人工判定六个字段。

| 指标 | 结果 |
|---|---|
| 首测通过 | **19 / 20** |
| 复测通过 | **17 / 18** |
| 字段级准确率 | **100%**（102 / 102 字段） |
| 硬信息错误 | **0**（日期、金额、份数、盖章） |
| 单条出卡用时 | 中位 **8.9 秒** |

唯一未通过的一条，原文只有一句「工作底稿原文·带附件」，**附件本体没提供**——模型正确识别了附件名、没有编造字段，但给不出完整清单。归因：素材缺失，不是抽取能力问题。

## 已知局限

1. 待确认没有字段级锁定——回答一条，可能把整个数组清空
2. 图片输入（OCR 路径）的 2 条用例未纳入复测
3. 第 5—8 步（催办 / 核验 / 未交名单 / 日历）目前是设计稿
4. 没有公开 Web 入口——AgentArts 当前版本只支持 IAM 认证的 API/MCP
